# 11 可用性与降级（availability-strategy-reviewer）

## Summary

Aurora 的可用性目标不是「服务不中断」，而是 **「任何外部能力缺失都能继续用，且用户知道发生了什么」**。
本文给出能力探测矩阵、单点故障清单与恢复流程；所有降级路径都对应到现有行为或 `13-roadmap` 的验收项。

## 能力探测矩阵

| 能力 | 探测方式 | 缺失/异常时的行为 | 用户可见提示 | 恢复动作 |
| --- | --- | --- | --- | --- |
| Edge WebView2 | 读注册表 `EdgeUpdate\Clients` 中存在 WebView2 项 | 回退 Qt 内核（`gui=qt`） | 无需提示（外观差异可忽略） | 装 WebView2 运行时 |
| 数据目录可写 | 目录创建 + 写探测文件 | 回落 `%LOCALAPPDATA%\aurora-launcher` | 设置页展示实际数据目录 | 用户设置 `AURORA_DATA` |
| 单实例 | 命名互斥量（`ERROR_ALREADY_EXISTS`） | 拉起已运行窗口并退出本次启动 | 无（行为符合预期） | —— |
| Locale Emulator | `PATH` + 常见目录探测，校验四件套 | 普通方式启动 | 面板提示「未装 LE，已普通启动」 | 装 LE 或手动指定 `LEProc.exe` |
| 转区目标位数 | 读目标 exe PE 头 | 目标为 64 位时不做转区 | 提示「LE 只支持 32 位目标」 | —— |
| TextractorCLI | `PATH` + 常见目录 + 用户指定路径；按 PE 位数挑 x86/x64 | 回退 OCR；无法 attach 时给状态 | 面板提示并提供下载页 | 装 Textractor 或手动指定路径 |
| 文本源健康度 | CLI 退出/管道 EOF/长时间无输出 | 会话标记不可用 | `vntext:status` + 一次提示 | 重开翻译 / 换 OCR / 换 hook 码 |
| Windows 日语 OCR | `available_recognizer_languages` 按主语言匹配 | OCR 模式不可用 | 一键跳转「语言和区域」设置 | 安装日语 OCR 组件 |
| 外部解压器 | `PATH` + `Program Files`（7-Zip / WinRAR） | zip 仍自动解压；rar/7z 不解压 | 提示「装个 7-Zip 或 WinRAR」并保留原包 | 装解压工具 |
| 网络 / 代理 | 端点连通性测试（5 个端点） | 自动换直连（可关）；失败仅影响联网功能 | 设置页展示生效路线与耗时 | 手动代理 / 直连 |
| 磁盘空间 | 写入失败捕获 | 素材不落盘、库写入保留内存状态 | 提示写入失败 | 清理空间 / 换数据目录 |

## 可用性设计要点

1. **外部工具一律「探测 → 校验 → 使用 → 降级」**，不在启动路径上做强依赖；缺工具不拦启动。
2. **子进程隔离**：TextractorCLI / LEProc / 解压器都是独立进程，退出与异常不影响主进程；主进程只处理
   「管道 EOF、退出码、超时」三种信号。
3. **高风险操作按需触发**：钩子查找器（调试器 + 硬件断点）与内存扫描只在用户主动操作或翻译需要补全时运行；
   内存访问全程只读。
4. **数据可恢复**：库文件写入走「临时文件 + 替换」，v2 增加备份与校验；强杀进程后重启要对账会话。
5. **常驻能力**：托盘常驻让游戏不被中断；心跳（30s）保证「先关启动器再关游戏」的时长可补记。
6. **失败要可见**：每个降级都要有一条事件或面板状态，不允许静默失败（例外：事件推送到已销毁窗口时静默丢弃）。

## 单点故障清单

| 单点 | 故障表现 | 影响面 | 处理 |
| --- | --- | --- | --- |
| 主进程 | 崩溃 / 被强杀 | 界面与后台任务全部停止（游戏不受影响） | 重启后对账会话；托盘常驻降低发生概率 |
| 数据目录 | 不可写 / 磁盘满 | 设置、库、素材无法落盘 | 内存状态保留 + 明确提示；回落目录 |
| `library.json`（v1） | 损坏 / 半写 | 库不可读 | 临时文件+替换已避免半写；v2 增加备份与校验 |
| TextractorCLI | 无输出 / 提前退出 | 翻译不可用 | 回退 OCR；状态可见 |
| OCR 引擎 | 语言缺失 / 截图黑屏 | OCR 不可用 | `PrintWindow` → `BitBlt` 回退；抬窗；提示 |
| 本地资源服务 | 端口占用 / 启动失败 | 界面资源加载失败 | 取空闲端口；失败时回落到「打包目录直接服务」的既有方式 |
| 网络 | 断网 / 代理坏 | 元数据与翻译不可用 | 直连切换；离线仍可管理本地库与启动游戏 |
| 系统代理配置 | 注册表读取异常 | 联网体验下降 | 探测失败按直连处理并提示 |

## 恢复流程

### 启动时的对账（沿用并强化现有逻辑）

1. 读库 → 若解析失败：尝试最近备份 → 仍失败：重命名为 `library.corrupt-<ts>.json` 并起空库（保留文件）。
2. 对每个 `play_started_at > 0` 的游戏：进程仍在跑 → 重新接管（显示运行中、结束时累计）；
   已结束 → 用 `play_heartbeat` 补记时长。
3. 清理过期缓存与残留临时文件；重建素材索引。

### 运行中的自愈

| 场景 | 自愈动作 |
| --- | --- |
| 代理路线失败 | 按设置自动换直连并记录一次诊断事件 |
| 图片 URL 失效 | 保留占位图，不阻塞其它内容 |
| 翻译接口失败 | 保留上一句译文，提示一次，下一句重试 |
| CLI 会话断开 | 结束文本会话 → 状态置不可用 → 允许重开或切 OCR |
| 悬浮窗被游戏全屏顶掉 | 用户可用热键显示/隐藏；不做抢占式置顶 |

### 退出与崩溃后的清理

- 正常退出：按 `08` F7 的顺序关停，确保不残留 TextractorCLI / OCR 任务 / 定时器。
- 崩溃退出：下次启动检测到「上次未正常退出」标记 → 主动清理孤儿 `TextractorCLI.exe`（仅在无人 attach 时）
  并在诊断包里记录一次。

## Evidence vs assumptions

- **证据**：探测方式与降级行为全部来自现有实现（WebView2 注册表探测、LE 四件套校验、PE 位数判定、
  解压器探测、OCR 主语言匹配、代理换路、心跳对账）。
- **假设**：用户接受「功能降级但要解释清楚」而不是「缺依赖就拒绝启动」；这与产品定位一致。
- **不确定**：孤儿 CLI 进程的识别需要额外实测（是否可能误杀用户自己开的 TextractorCLI）→ 只清理
  「由本进程启动且父进程已消失」的实例，作为 P3 的实验项。

## Risks or tradeoffs

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 降级路径过多 | 组合爆炸，难测试 | 用矩阵 + fake 适配器覆盖关键分支（`13` 的测试计划） |
| 自动清理误伤 | 杀掉用户自己的 CLI | 只清理本进程启动且父进程已消失的实例；默认不清理 |
| 备份目录膨胀 | 每次迁移都留备份 | 只保留最近 3 份 + 手动清理入口 |

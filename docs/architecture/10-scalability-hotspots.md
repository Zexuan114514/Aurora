# 10 容量热点（scalability-hotspot-detector）

## Summary

这里的「伸缩」不是并发用户，而是**游戏库规模、事件频率、磁盘与内存占用**。共识别 9 个热点，
每个都给触发阈值与缓解方案；当前 24 款游戏的规模下多数还没触线，但 H1/H4/H8 已经能被用户感知。

## 热点清单

| # | 热点 | 假设负载 / 阈值 | 现状表现 | 缓解（归属阶段） |
| --- | --- | --- | --- | --- |
| H1 | `library.json` 全量重写 | 500 款游戏 ≈ 6 MB/次；每次设置变更都触发 | 24 款 = 297 KB，改一个设置就重写整库 | 分账（settings / library / sessions）+ 去抖 + 单写者（P2） |
| H2 | 全量快照推送 | `bootstrap()` 一次推 500 条 PublicGame（约 2 MB JSON） | 24 条无所谓 | 首屏只推大厅所需字段；详情按需拉（P3 契约扩展，需 ADR） |
| H3 | 前端 DOM 规模 | 环形大厅节点数 = 游戏数；> 200 时布局与合成压力上升 | 24 个节点，流畅 | 虚拟化/窗口化（只渲染可视 ±N）；布局用 transform 不触发布局（P4） |
| H4 | 事件推送频率 | 快速翻页 + 流式译文 = 每句 3–5 次 `evaluate_js` | 已能感到悬浮窗刷新频繁 | 节流合并（100ms）+ 单调 seq + 同主题覆盖式更新（P3） |
| H5 | 翻译请求串行队列 | LLM 1–3s/句；连续翻页 20 句 | 已改成队列（不掐断） | 并发上限 1–2 + 缓存命中优先 + 超时重试策略（P3） |
| H6 | OCR 采样循环 | 0.9s/次截图 + OCR；长时游戏数小时 | CPU 占用与耗电 | 帧差检测（画面无变化不 OCR）+ 可调间隔 + 空闲暂停（P6 规则化） |
| H7 | 只读内存扫描补全 | 每句一次全内存扫描 → 热区缓存 | 已有热区缓存 | 热区命中率指标 + 扫描上限（区域数/字节数）+ 超时放弃（P6） |
| H8 | 日志与缓存增长 | 当前日志单文件 8.8 MB（512 KB 滚动）；缓存仅 90 天兜底清理 | 日志已明显偏大 | 结构化日志 + 分级 + 按天滚动 + 诊断包按需导出（P7） |
| H9 | 图片与素材体积 | 每游戏 30+ 张背景图（README 实测 34 张） | 磁盘占用随库线性增长 | 只缓存命中的图；缩略图与主图分离；提供「清理未使用素材」入口（P5） |

## 阈值与观测点

| 指标 | 采集方式 | 警戒线 |
| --- | --- | --- |
| 库文件大小 / 单次写入耗时 | 写入前后打点（结构化日志） | 文件 > 5 MB 或单次写 > 100ms |
| 事件推送 QPS | EventBus 计数 | 持续 > 20/s |
| 大厅首屏渲染耗时 | 前端性能打点 | > 300ms |
| 翻译队列积压 | 队列长度 | > 5 句 |
| OCR 单次耗时 | 采样耗时统计 | > 400ms |
| 内存扫描命中率 | 热区命中 / 扫描次数 | < 50% |
| 日志日增量 | 文件大小 | > 5 MB/天 |
| 素材总量 | 目录统计 | > 2 GB |

## Findings

1. **真正的写放大在 H1**：单文件全量重写把「改一个设置」变成「重写全部游戏记录」，
   P2 分账后设置写入应降到常量级；这也是迁移到 v2 的最大收益。
2. **事件风暴是体验问题而不是性能问题**：H4 的缓解（合并 + 覆盖式更新）比「优化 JSON 序列化」更有效。
3. **H6/H7 是长时游戏的隐性成本**：OCR 与内存扫描都在「每句都做」的路径上，需要节流与放弃策略，
   否则玩家会感到风扇转速上升。
4. **H8/H9 属于运维债**：不是功能问题，但直接影响用户对「干净工具」的评价。

## Evidence vs assumptions

- **证据**：H1/H8/H9 的数值来自当前 `data/` 目录实测（297 KB 库、8.8 MB 日志、34 张背景图的实测记录）；
  H5/H7 的行为来自现有实现（翻译队列、热区缓存）。
- **假设**：中位库规模 20–100 款（当前 24 款），上界 500 款；事件频率上限按「人工翻页速度」估算（约 2 句/秒）。
- **不确定**：H3 的具体阈值（200 款是否真的开始卡）需要 P4 用 200/500 条构造数据实测后回填。

## Risks or tradeoffs

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 过早优化 | 24 款规模下做虚拟化收益低 | 只做有阈值数据支撑的项；H3 的实现在 P4 之后再定 |
| 节流伤害实时性 | 事件合并可能让流式译文变卡 | 合并窗口 100ms；首 token 与完成事件不合并 |
| 素材清理误删 | 用户自定义封面/背景被清掉 | 清理只针对「未被任何游戏引用」的对象，且先出预览清单 |

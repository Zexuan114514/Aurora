# ADR-0011：密钥明文存储 + 导出剥离

## 状态

已接受。

## 背景

翻译需要用户自己的 LLM API Key，当前作为 `settings.translate_api_key` 明文存在 `library.json` 里。
导出游戏库（`export_library`）会把整个 settings 一起导出 —— 意味着**导出的备份文件里带密钥**。
诊断包与日志也有泄露风险。

## 决策驱动

- 单机桌面程序、零新增依赖（不能用 keyring 之类的库）。
- 用户会把库文件分享/备份/贴到聊天里 → 导出路径必须安全。
- Windows 用户目录本身有访问控制，明文不是致命问题，但传播路径必须收口。

## 考虑过的选项

1. **明文存储 + 导出剥离**（当前数据布局 + 导出改造）。
2. **DPAPI 加密**（`CryptProtectData`，零依赖但机器绑定）。
3. **要求环境变量**（`AURORA_TRANSLATE_KEY` 之类）。

## 决定

选择 **1**，并把 2 记为后续可选项：密钥继续存 `state/settings.json` 明文；
**导出文件、诊断包、日志一律剥离或脱敏**；界面在填写处提示「密钥只存在本机数据目录」。
若将来要做 DPAPI，必须处理「换机后密钥失效」的迁移提示，届时另立 ADR。

## 后果

- ✅ 导出与分享路径安全；用户无需额外配置。
- ⚠️ 本机明文仍存在 → 依赖 Windows 用户目录权限；文档需如实说明。
- ⚠️ 迁移 v1 → v2 时，密钥字段必须原样保留且不写入日志。

## 后续动作

- P2 实现导出剥离 + 单测断言导出 JSON 中 `translate_api_key` 为空。
- P7 诊断包脱敏规则与此保持一致（共用一份脱敏函数）。

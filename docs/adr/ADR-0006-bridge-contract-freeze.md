# ADR-0006：桥接方法名冻结 + 事件信封

## 状态

已接受。

## 背景

pywebview 只暴露 `js_api` 对象的**顶层**方法；当前 `gl/api.py` 的 `Api` 类有 146 个方法
（105 公开 / 41 内部），前端有 96 个调用点；悬浮窗另有 4 个方法。事件目前靠
`window.evaluate_js` 拼接 JS 字符串推送，共有 14 个主题。契约检查只有一个正则脚本，且不在 CI 里。

## 决策驱动

- 前端是唯一的界面，方法名漂移 = 功能静默失效。
- 迁移期要「边拆边可用」，必须能机械验证。
- 事件推送需要统一格式（顺序、去重、背压、窗口无关）。

## 考虑过的选项

1. **冻结方法名，重构只在内部**：mixins 聚合出单一 `js_api` 对象。
2. **重新设计桥接命名（分组对象 / RPC 风格）**：pywebview 不支持嵌套对象 → 需要自研路由。
3. **自动生成前端调用代码**：无构建链下收益有限。

## 决定

选择 **1**。规则如下：

- 方法名与语义冻结；工程内部拆成 `ui/bridge/*` mixins，聚合类仍是单一 `js_api` 对象。
- 契约快照进版本控制（`contracts/bridge-contract.json`），CI 对比方法名集合，diff 必须为 0。
- 前端所有调用统一走 `core/api.js`，页面代码禁止直接访问 `window.pywebview.api`。
- 事件统一为 `{topic, seq, ts, payload}` 信封，用单个 JSON 字符串分发（禁止字符串拼接）。
- 破坏性变更（改名、删字段、改语义）必须走 ADR + 前端同步迁移。

## 后果

- ✅ 迁移期可以逐个方法搬迁并保持界面可用。
- ✅ 契约有了机器可读的真相来源，文档与测试都引用它。
- ⚠️ 「只增不改名」会让方法名长期保留历史包袱 → 允许新增更合适的新方法并在 ADR 里标注旧方法待废弃。

## 后续动作

- P0 生成快照并加 CI 检查；P3 每完成一批搬迁跑一次 diff。
- 事件信封与主题表见 `contracts/events.md`。

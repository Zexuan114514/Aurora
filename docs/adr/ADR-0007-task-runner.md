# ADR-0007：显式任务执行器替代散落线程

## 状态

已接受。

## 背景

当前有 18 个具名线程（心跳、会话监控、CLI 读循环、OCR 循环、翻译队列、批量任务、下载监听、
托盘、热键、悬浮窗等），全部由各处 `threading.Thread(...).start()` 就地创建，没有统一的
命名规范、取消机制、超时与关停顺序；组件之间通过构造器回调（`on_line` / `on_status` / `on_found` / `on_exit`）连接。

## 决策驱动

- 关停顺序可控（退出时不能留残留子进程/线程）。
- 取消与超时是一等公民（翻译、批量任务、钩子查找都需要可中断）。
- 离线测试需要「不用真线程也能跑」的接缝。

## 考虑过的选项

1. **保持散落线程 + 各处自管停止标志**。
2. **统一 TaskRunner 端口**（命名、有界、可取消、带超时）+ 事件总线替代回调。
3. **引入 asyncio**：与 pywebview/ctypes 阻塞调用混杂，改动面过大。

## 决定

选择 **2**。`TaskRunner` 由 `app/ports.py` 定义、`infra/tasks.py` 实现（`concurrent.futures` + `queue`），
按域分配有界池（IO 密集 / CPU 密集分开），任务必须有名字、超时与取消路径；
组件间通信用 `EventBus`，不再用构造器回调互相注入。

## 后果

- ✅ 退出流程可枚举、可断言（P3 增加「退出后无残留子进程/任务」测试）。
- ✅ 线程表格化（见 `08-runtime-views.md` 的映射清单），排错时能按名字定位。
- ⚠️ 自研执行器需要自己处理异常吞没、队列上限与死锁 → 保持实现小而透明，并写单测。
- ⚠️ 迁移期两套并存，容易出现「新任务用 TaskRunner、旧代码自己起线程」的混乱 → P3 一次性收口。

## 后续动作

- 按 `08` 的映射表逐个搬迁，每搬一个删除旧线程创建点。
- 增加测试：任务超时、取消、异常隔离、关停顺序、退出后无线程存活。

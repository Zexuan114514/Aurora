# ADR-0010：结构化日志与诊断包（脱敏）

## 状态

已接受。

## 背景

当前日志是 `data/aurora.log` 的纯文本追加（512 KB 滚动一次，保留一份），实测已经到 8.8 MB；
排错时要靠用户在会话里贴长文本，且日志里可能出现密钥（设置里有 `translate_api_key`）。
同时 `gl/config.py` 的 `log()` 是全局函数，没有级别、没有子系统、没有字段。

## 决策驱动

- 真机问题（钩子缺字、OCR 质量、会话结算）必须能靠日志定位，不能靠复现。
- 隐私：日志与诊断包不得泄露 API Key；导出库文件也不得带密钥（ADR-0011）。

## 考虑过的选项

1. **保持文本日志**。
2. **结构化日志 + 内存环形缓冲 + 一键诊断包**（零依赖实现）。
3. **引入 structlog/opentelemetry**：与 ADR-0003 冲突。

## 决定

选择 **2**。日志行含 `ts` / `level` / `subsystem` / `fields`（如 `game_id`、`engine`、`thread_key`、`pid`）；
按大小与日期滚动到 `data/logs/`；内存保留最近 200 条供诊断包使用；
诊断包内容 = 版本 / 能力探测结果 / 生效设置（脱敏）/ 最近 200 行日志 / 线程与任务清单 / 迁移与备份状态。

## 后果

- ✅ 排错从「贴长文本」变成「导出一个压缩包」。
- ✅ 日志级别可调（默认 info，调试模式 debug），噪声可控。
- ⚠️ 日志写入需要去抖/批量，避免高频写盘（`10` H8）。
- ⚠️ 脱敏规则必须单测覆盖（`*_key`、`*token*`、URL 里的 `api_key=` 查询参数）。

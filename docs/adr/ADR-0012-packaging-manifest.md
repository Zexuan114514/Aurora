# ADR-0012：打包清单单一来源

## 状态

已接受。

## 背景

`tools/build_exe.py` 里硬编码了要打进 exe 的前端文件（`index.html` / `app.css` / `app.js` / `overlay.html`）
与要排除的用户素材目录。前端一旦模块化成多个目录（`app/`、`core/`、`views/`…），这份硬编码就会漏文件；
同时运行时的资源定位逻辑也必须知道「哪些是随包资源、哪些在数据目录」。

## 决策驱动

- 前端模块化（ADR-0002）与资产服务化（ADR-0005）都要求资源清单可维护。
- 用户素材绝不能进发布包（历史踩坑）。
- 打包失败必须早、明确、可解释。

## 考虑过的选项

1. **继续在构建脚本里硬编码**。
2. **单一清单**（资源树 + 排除项 + 动态导入声明），构建脚本与运行时共用。
3. **用 PyInstaller spec 文件作为唯一真相**：需要额外维护 spec，且运行时读不到。

## 决定

选择 **2**。新增一份清单（如 `packaging/manifest.py` 或 `packaging/manifest.json`）声明：
随包前端资源树（含扩展名过滤）、必须排除的用户目录、winrt 动态导入模块、体积排除项；
`tools/build_exe.py` 据此暂存与打包，运行时据此定位资源根目录。

## 后果

- ✅ 前端加一个模块不会忘记打包；运行与构建对「资源在哪」有一致理解。
- ✅ 可在 CI 做「打包 dry-run」：断言清单里的文件全部存在、排除项没有混入。
- ⚠️ 清单本身要版本化（P0 起纳入契约），避免运行与构建版本不一致。

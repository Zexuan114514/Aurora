## 1. 强调色胶囊：文字换行 / 溢出

**现象**：设置 → 外观 →「强调色」那一排胶囊里，名字被拆成两行（「跟随 / 主题」「薄荷 / 青」…），
最后一个「自定义」直接竖排并溢出虚线框。

**复现**：任意主题、任意窗口宽度都能看到（与窗口大小无关，是固定几何）。

**实测**（真机 DOM 量出来的，探针见文末）：

| 元素 | 实测 | 应该 |
| --- | --- | --- |
| 4 个胶囊内的 `span` | CSS `width: 34px`、`line-height: 17.25px`、实际高 **35px**（两行） | 宽随文字、单行 |
| `.palette-custom`（「自定义」，本身就是个 `span`） | 宽 34px、`scrollHeight > clientHeight`（**溢出了**） | 宽随文字、30px 单行 |
| 胶囊本体 `.palette-chip` | 高 30px | 不变 |

**根因**：`frontend/src/styles/layout.css:1280` 那条 v1 迁移过来的规则

```css
.set-row span { width: 34px; text-align: right; font-size: 11.5px; }
```

本来是给「设置行尾那个数值位」用的，但它是**后代选择器**，于是命中了
`.palette-chip > span` 和 `.palette-custom`（后者本身就是 `span`）——
和 P8.1/P8.2 修过的 `el-switch` / `el-slider` / `el-button` / `el-input` 是同一类泄漏
（那些还原规则现在在 `frontend/src/styles/element.css` 的「设置页」小节里）。

**建议改法**（任选，都是一两行）：

1. 在 `element.css` 那段还原块里补上 `.palette-row span, .palette-custom { width: auto; text-align: left; font-size: 12px; }`；或
2. 把 `layout.css:1280` 收紧成 `.set-row > span`（**要先确认**别的行没有靠这条规则命中深层 `span` ——
   出问题的 `.palette-chip > span` 与 `.palette-custom` 都在「强调色」那一行里；
   `.theme-card span` 在 `.theme-cards` 里、不在 `set-row` 内，所以它没被波及）。

顺手可以给胶囊文字加 `white-space: nowrap`，避免以后名字变长又换行。

**验收**：外观面板截图 + 一条几何断言（每个胶囊 `span` 的 `scrollWidth <= clientWidth + 1` 且高度 ≤ 30）。

**已修（2026-09-22）**：按上面第 2 条思路把 `layout.css:1280` 收紧成 `.set-row > span` ——
一个选择器改一行，胶囊、`el-switch` 内部、`el-input` 内部三处泄漏一起消失
（`element.css` 里那些「还原」规则留着当第二道保险）。真机复测：4 个胶囊的 `span` 宽 34 → 随文字、
高度 35 → 17（单行），`.palette-custom` 不再 `scrollHeight > clientHeight`。

## 2. 四套主题区分度不足

**现状实测**：拿现有的主题截图基线（`tools/baselines/theme-baseline.json`，16×10 网格平均色）
比「同一界面、四套深色主题」两两之间的色差：

| 组合 | 平均色差（0–255） | 最大 |
| --- | --- | --- |
| aurora vs gallery | 6.1 | 51 |
| aurora vs screening | 11.3 | 70 |
| aurora vs shelf | 8.5 | 49 |
| gallery vs screening | 7.2 | 54 |
| gallery vs shelf | 3.9 | 57 |
| screening vs shelf | **3.5** | 40 |
| 合计平均 | **6.8** | 70 |
| 参照：同一主题 深 vs 浅 | **213.7** | — |

也就是说：深浅两态差了 213，四套风格之间只差 6.8 —— 使用者感知到的「换主题」≈ 换一个强调色。

**为什么会这样（结构性原因，不是没调好）**：ADR-0013 定的是「**布局只有一套，风格全在令牌**」，
并且把这条钉死在守卫里：

- `tools/checks/check_theme_contract.py:24` `SKIN_MAX_LINES = 80`，`:145` 超了就红；
- `frontend/src/styles/themes.spec.ts:58` 是它的 JS 镜像；
- 每个皮肤文件的选择器必须挂在自己的 `[data-style="…"]` 下，**不许碰布局的通用规则**。

于是主题能改的只有颜色、圆角、阴影、模糊这类令牌值；字体排印、分隔线、封面呈现方式、
列表行密度、背景处理这些都动不了 —— 而这恰好是参考图里各主题真正的差异来源。

**参考图（使用者提供的目标形态）**：

> 另有一组**可打开的示例主页**：[`theme-demos/`](theme-demos/index.html) ——
> 同一个内容（6 款游戏、同一套封面）用四种设计语言各做一遍（独立静态 HTML，
> 无构建、无外链、双击即开），并把每套改了什么、对应哪些令牌写在
> [`theme-demos/README.md`](theme-demos/README.md) 里，可直接照着往皮肤层搬。

| 主题 | 参考图 | 里面真正改了什么（可落成任务） |
| --- | --- | --- |
| 展签式画廊 | [`ref-theme-gallery.jpg`](images/ux/ref-theme-gallery.jpg) | 标题与元数据**直接压在画面上**（没有卡底），用一条细线分隔；无圆角、无投影；列表行更矮；标题更大、字距收紧，元数据更轻 |
| 夜间放映厅 | [`ref-theme-screening.jpg`](images/ux/ref-theme-screening.jpg) | 暖黑底 + 琥珀；主封面像「正在放映」（外发光/光晕）；标题与元数据之间一条琥珀细线；列表时间与底部信息条用琥珀 |
| 极光玻璃精修 | [`ref-theme-aurora.jpg`](images/ux/ref-theme-aurora.jpg) | 保留毛玻璃但**收敛高光**（别把白面提太亮）、强调色回到极光青紫、阴影更柔 —— 也就是现在这套的精修版 |
| 收藏架 | [`ref-theme-shelf.jpg`](images/ux/ref-theme-shelf.jpg) | 封面**立在架上**（底部一条实体横档 + 落影）；黄铜色分隔；说明卡像纸质（微暖白、轻纹理）；底部信息条带横档 |

**建议做法**：

1. 把「主题签名」从纯换色扩到四类：**字体排印**（字号/字距/字重）、**分隔与框架**
   （细线、横档、边框）、**封面呈现**（卡底/外框/落影/架子）、**背景处理**（暗化、渐晕、颗粒）。
2. 给 DOM 加**结构性钩子**（例如 `data-slot="title" / "meta" / "rail"` 这类不参与语义的标记），
   让皮肤能选中它们 —— 但**不许改几何与 id**（环形几何与 92 个探针 id 是冻结面）。
3. 相应放宽 `SKIN_MAX_LINES`（80 → 200 量级）并允许皮肤使用这些钩子；
   `check_theme_contract.py` 与 `themes.spec.ts` 同步改，改前先想清楚「皮肤不许改布局通用规则」这条还怎么守。
4. 素材：参考图里用了各主题自己的分隔线/纹理/光晕 —— 尽量用 CSS（渐变、`box-shadow`、`mask`）
   做，实在要位图就放进 `gl/assets/themes/<style>/`，并进打包清单（`tools/build_exe.py`）。

**验收**：

- 主题截图矩阵（25 张）继续全绿 —— 现有基线会因为皮肤增强而变，需要重录一次并人眼过一遍；
- 新增一个「区分度」下限，用现成的指纹就能算：**深色四套两两平均差 ≥ 20/255**（现在是 6.8），
  写进 `tools/visual.py` 的主题段，避免以后又退回「换个强调色」。

**尺子已就位（2026-09-22，同轮次的 P8.3）**：`tools/visual.py` 的主题段现在会算
「深色四套两两平均色差」并写进报告 / `visual_summary.py` 汇总，目标 ≥ 20。
当前实测 **8.6**（参照：深/浅两态 193；逐对最弱的是 aurora vs gallery 5.0）。
只报数不判红 —— 等皮肤真的改到位再让它变红，免得长期挂着一条红的。
应用侧同步做掉的两件是「极光去掉轻模糊」与「常驻背景图」，见
[`architecture/p8-frontend-v2.md`](architecture/p8-frontend-v2.md) 的 P8.3 小节。

**已修（2026-09-22，P8.4）**：把示例页里四类签名（背景处理 / 排印 / 分隔与框架 /
封面呈现）搬进皮肤层，并按主题做表面色温分层 —— 区分度 **8.6 → 20.4**
（逐对最弱的 aurora–screening 13.7，最强的 screening–shelf 30.0；参照：深/浅两态 173）。
25 张主题矩阵重录后逐张比对偏差 0，ring 判据一字未动。做法、逐轮数字与踩到的
「令牌只写深色块」回归都在 [`architecture/p8-frontend-v2.md`](architecture/p8-frontend-v2.md) 的

## 3. 深色态在亮壁纸上文字不可读（设置页 / 游戏详情页）

**现象**：明暗选「深色」时，设置页的说明文字、游戏详情页的标题/元数据/简介仍是**白色**，
而它们底下的毛玻璃把亮壁纸透上来，于是变成「亮底白字」，几乎看不见。

**实测**（真机取「文字正下方 8px 的等宽像素带」当底色，文字色取 `getComputedStyle`，
按 WCAG 算对比度；正文要求 ≥ 4.5，大字号 ≥ 3.0）：

| 位置 | 深色态 | 浅色态（对照） |
| --- | --- | --- |
| 设置页 · 说明文字 | aurora **3.13** / gallery **3.31** / screening **1.15** / shelf **1.04** | 12.9 – 15.1 ✓ |
| 游戏页 · 标题 | 2.04 – 2.54 | 7.9 – 8.5 ✓ |
| 游戏页 · 元数据行 | 1.92 – 2.44 | 7.3 – 8.0 ✓ |
| 游戏页 · 简介 | 1.04 – 1.76 | 9.4 – 10.7 ✓ |

同一套主题、同一张壁纸，只把明暗从深切到浅，对比度从 ~1.0 跳到 ~10 —— 问题不在壁纸，在深色态的取色方式。

**根因**：面板背景**没有暗底**，只有一层很淡的白色叠加 + 模糊：

- `frontend/src/styles/layout.css:106` `.glass` 的 background 是
  `linear-gradient(… var(--srf135), var(--srf055), var(--srf035))` + `backdrop-filter: blur(...)`；
- `frontend/src/styles/tokens.css:19` `--ramp-s: 255 255 255`（**深色态也是白**）、`:80-90` 的
  `--srf035 … --srf090` 把白面按 3.5% – 9% 的透明度铺上去。

于是深色态的面板 ≈ 96% 的壁纸 + 4% 的白，壁纸亮 → 面板亮，而文字是纯白（`--text-1: #ffffff`）。
screening / shelf 的次级文字本来就偏暖灰（`--text-2: rgb(203 186 164 / .92)`、`rgb(183 173 158 / .94)`），
叠在暖色亮底上就更糊，这也是它们只有 1.0 出头的原因。

**为什么现有守卫没拦住**：主题契约（`check_theme_contract.py`）只检查「令牌补齐了没」，
不检查「补的值能不能看」。也就是 e2e / visual 全绿，但真的看不见。

**建议改法**（三档，可组合；第 1 档能立刻缓解，第 3 档最稳）：

1. **给游戏页文字加一层保底**：标题 / 元数据 / 简介块底下铺一条暗色渐变（或半透明面板），
   与壁纸亮度解耦。改动只在 `GameView` 的样式层，风险最小。
2. **给 `.glass` 加暗底**：深色态在现有白色高光下面再垫一层
   `color-mix(in srgb, var(--s-panel) 55%, transparent)`（或把 `--ramp-s` 在深色态换成深色基色）。
   代价：四套主题的面板观感都会变，`tools/baselines/theme-baseline.json` 需要重录，
   并且要重新确认「极光玻璃」那种透亮质感还在。
3. **按壁纸亮度自适应**：背景层已经知道当前壁纸（`BackgroundLayer` 会预载图片），
   可以采样一次平均亮度，写进一个 `--bg-lum` 变量，让深色态面板的底衬
   在「亮壁纸」时更厚、「暗壁纸」时更薄 —— 观感最接近设计意图，但要新增一条运行时链路。

顺带：用户能自己调的 `scrim`（`aurora/infra/config.py:74`，默认 42%）能救一点，
但它是全局的、藏在背景面板里，指望用户自己找到不现实。

**验收**：把本文用的测量方法固化成 `tools/contrast.py`（真机跑、可重复，用法跟 `tools/visual.py` 一样，
输出每个「主题 × 明暗 × 页面」的最小对比度表），阈值取 正文 ≥ 4.5 / 大字 ≥ 3.0，
然后把它接进真机验收那一档（`e2e` / `visual` 同级）。

**已修（2026-09-22）**：查下去发现是**两个**问题叠在一起，都不只是取色问题：

1. **面板没有底色**。`.glass` 只有一层 3.5%–13.5% 的白（`--srf035…135`）加模糊，
   `.set-nav` / `.set-panes` 更直接是 `--srf070`（7% 白）；深色态 = 96% 的壁纸 + 4% 的白。
   修法：新增派生令牌 `--s-floor: color-mix(in srgb, var(--s-panel) 68%, transparent)`，
   给 `.glass`、`.set-nav`、`.set-panes`、`.glass-s`、`.btn.glass-btn` 垫一层底色
   （浅色态 `--s-panel` 是白，等于不变；深色态才是暗底）。
2. **游戏页的 scrim 一直是死代码**。`#bg-scrim` / `#bg-vignette` 写的是
   `rgba(var(--scrim-rgb), α)`，而 `--scrim-rgb` 是空格分隔的三通道（`0 0 0`）——
   这是**非法语法**，浏览器把整条 `background` 丢掉，也就是说「按壁纸明暗压暗」这个功能
   从来就没生效过（computed `background-image` 是 `none`，实测）。改成 `rgb(var(--scrim-rgb) / α)`
   之后 scrim 才真正开始工作；再给游戏页加一层「不随用户 scrim 归零」的保底（`body.page-game`）。 
3. 顺带把深色态的次级文字调亮（screening / shelf 的 `--text-2` / `--text-3` 是暖灰，
   叠在暖色亮底上最糊），并把设置页的说明文字从 `--text-3` 挪到 `--text-2`。

  保证当前游戏在可视区里；

### 合成事件全绿但真机还是点不动 —— 真凶是环形视口盖住了侧栏

使用者复测后说：「拖滑动条 / 点一行 / 悬停反馈」**全都没感受到**。
改用**真·鼠标（`SendInput`）+ 命中测试**重查（`_sandbox/probe_real_mouse.py`），
一眼就看出问题了：

```
hitRow （侧栏一行的正中）  → ["div#hallViewport.hall-viewport", "span.row-title", …]
hitBar （滚动条那一条）    → ["div#hallViewport.hall-viewport", "div#hallSideRows", …]
viewportRect → rect [0,0,1356,718]  display: block  pointer-events: auto
```

**根因**：列表布局下 `#hallViewport`（环形容器）**仍然 `display:block` 且铺满整个大厅**，
DOM 顺序又在 `.hall-list-body` 之后，于是它压在右侧栏上面，把真实鼠标的
hover / click / 拖动滚动条**全部吃掉**。合成事件（`element.click()`、`dispatchEvent`、
`scrollIntoView`）都绕过了命中测试，所以前两版探针全绿 —— 这是这次踩得最深的坑。

**修法（一行）**：`#hall.hall-list .hall-viewport { pointer-events: none; }`
（只关命中，不动几何；切回 ring / flat 立即恢复）。

**修后同一套真机探针**：

| 检查 | 修前 | 修后 |
| --- | --- | --- |
| 侧栏一行的命中元素 | `#hallViewport` | `span.row-title` → `button.hall-row-item` ✓ |
| 滚动条那一条的命中元素 | `#hallViewport` | `div#hallSideRows` ✓ |
| `#hallViewport` 的 `pointer-events` | `auto` | `none` ✓ |

**教训（已写进交接文档）**：真机行为要用**真鼠标 + `elementsFromPoint`** 验，
合成事件只能验逻辑，不能验「点得到」。

## 10. 展签式画廊：背景饱和度过低

**现象**（使用者实机）：画廊一切过去，整屏像蒙了一层灰 —— 封面还在，壁纸被洗成灰白，
「展墙」是有了，但也丢了「画廊」该有的画。

**根因**：P8.4 为了做「夜里的展墙」，把壁纸处理写成
`filter: grayscale(0.62) brightness(1.08) contrast(0.95)`（浅色态 `grayscale(0.5)`）——
去饱和 62% 太重，颜色信息基本被抹平；而「冷灰」这个观感本来该由面板底色
（`--s-floor`、`#hall::before` 的冷灰罩）承担，不该靠把壁纸洗白来做。

## 23. 收藏架 / Atelier 在环形与平铺布局下的封面显示 + 深色背景过曝

**现象**（使用者实机）：
1. 这两种主题在**环形队列**与**平铺横滑**下，主页封面显示不对：
   竖版封面占不满整个封面框；横版封面只占封面框的上面一部分，甚至超出；
2. 这两种主题的**背景图在深色下有「过曝」观感**（问：是否有意为之）。

**根因（已定位，两条都在皮肤里）**：
1. **封面**：`.gi-cover`（`[data-slot="cover-art"]`）的基准样式是 `position: absolute; inset: 0`，
   而 shelf 的 P8.8 段落与 atelier 的皮肤都把它改成了 `position: relative` ——
   于是它不再铺满封面框，尺寸改由**图片自身比例**决定：2:3 的正常，
   更矮的竖版（如 3:4）下方留白、横版（如 Steam 头图 460×215）只占上半部分、
   更高的竖版则直接溢出。**不是"封面读不出来"，是那张皮肤动了不该动的 position。**
2. **背景过曝**：shelf 的 `.bg-img` 是 `sepia(0.42) brightness(1.14) …`，
   atelier 的是 `saturate(0.5) brightness(1.22) …` —— 这两个滤镜是**照浅色小样定的**，
   深色态也照用，等于把壁纸整体提亮。**不是有意为之**，属于漏做深浅分档。

**✅ 本轮已修（P8.18）**：
1. shelf 的那条 `position: relative` 删掉（`.bg-item` 本来就是 relative，不需要它；
   `.gi-cover` 恢复 `absolute; inset: 0`），atelier 皮肤里同样的一条也删了。
   **DOM 复验**（shelf / atelier × 环形 / 平铺，各 22 格逐格比对 `img` 与封面框的
   尺寸和偏移）：**尺寸不符 0 格、偏移全 [0,0]** —— 使用者库里的非 2:3 封面
   （411×560、791×560、1066×1507 …）现在都被 `object-fit: cover` 正确裁切填满。
2. 两种主题各补一条深色专用壁纸滤镜：shelf `brightness(0.88)`、atelier `brightness(0.84)`；
   **不是有意为之**，就是漏了深浅分档。

## 24. 移除游戏不立刻生效（要再启动一次才消失）

**现象**：游戏详情页移除某款游戏后，列表里还留着它，重启应用才不见。
